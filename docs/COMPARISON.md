## What this project is for

Choose this project when Codex CLI threads need enforced page ownership, visible thread groups, reusable tab slots and shared existing login state, while retaining the official MCP page-operation backend. Choose the official server directly for its broader DevTools surface and documented page routing or separate temporary profiles; consider mux for client-scoped sharing of a launched browser, agent-browser-mcp for a general extension/group workflow, or mcp-chrome for broader personal-browser tools. These are workflow recommendations based on the reviewed interfaces, not runtime quality or performance rankings. Shared profile cookies and account state remain shared across this project's workspaces.

## Our verification boundary

Version **0.3.1** was checked with WSL and Windows Chrome **156.0.8078.74**. Two explicitly synthetic fixture identities completed six alternating fresh screenshots, including full-page capture, and three recovery screenshots after failure/cancellation. A real admin Codex thread also captured successfully. During 116.7 seconds, 7,325 Windows samples recorded no foreground change or loss of minimized state; the original active tab was restored. This is sampled evidence on one environment, not a guarantee across Chrome releases or a complete multi-thread business acceptance test. See the [dated acceptance record](ACCEPTANCE.md).

Implementation references: [identity contract](../packages/adapter/src/identity.ts), [workspace ownership and capture serialization](../packages/adapter/src/workspaces.ts), [extension lifecycle](../packages/extension/worker.js), [pinned backend](../package.json), and [minimized capture helper](../scripts/upstream-capture.mjs). The helper temporarily enables a tiny screencast on the owned page session while the official screenshot runs, then stops it; it does not restore the window or call `Page.bringToFront`.
